# Package rewind (P2): rewind a chat and its files to an earlier message, and tell the model what was restored

## Log

2026-09-29. The fix first: an Undo used to change files under the model and tell it nothing (`session.ts` only emitted the event), so the next turn built on edits that were gone. Now, after any restore (Undo, Redo, a rewind), the next task's preamble names the files, once: `restoreNotes` in `os-code/src/core/agent/seed.ts` reads the journal after the last live task-start, so that task's own task-start clears the notes and a session revived after a restart still says them; `LocalDriver.pump` puts them between the handoff and the terminal context (loop.ts untouched). Then `LocalDriver.rewind(toSeq, { files })`: refused while a task runs, waits, or another rewind runs; with the files it undoes every later checkpoint newest first through the same restore Undo uses (one already undone is passed over); at the first failure it stops, journals a note naming what went back, and leaves the chat as it was; otherwise it journals `{ type: 'rewound', toSeq, paths, kept? }` and resets `agent.history` from `seedHistoryFromEvents`, which now leaves out everything from `toSeq` up to each marker (`liveJournal`), as the rehydrate seed does. `serve.ts` has `POST /sessions/:id/rewind` (the session owner's, like undo, body checked), and Electron has `guarded('osc:rewind', ...)` through `EngineHost.rewind`, the preload, and the bridge type; every driver forwards `rewind` (Electron, the daemon's `RemoteDriver`, the ethics guard). In the app, user items carry their journal `seq` (a phone's painted bubble takes it from the echo) and the transcript folds `rewound` by cutting from the first message at or after `toSeq`, with a quiet line saying what the files did, so a live fold, a replay, and a paired phone agree. Store logic is in `app/src/state/rewindOps.ts`; `store.rewindTo` asks the engine on a coding chat, or cuts the thread and rebuilds the brain from what is left on any other chat. UI: a quiet round "Rewind to here" action beside the person's own bubble on hover or focus (desktop), a long press with a tick on the phone, and Esc Esc in an empty desktop composer for the last message, all opening `RewindSheet` (on `<Sheet>` and `SheetHead`), whose choice hands the message back to the composer. Tests: engine `rewind.test.ts` (14) and `daemon.test.ts` (+1); the four preamble tests fail on the old `pump`. App `rewind.test.ts` (12), `rewindSheet.test.tsx` (6, including the chat screen refill), `rewindComposer.test.tsx` (1), `rewindStore.test.ts` (4), `mainIpc.test.ts` (+1). Gates: engine build, typecheck, lint, format green, 2067 passed and 2 skipped; app typecheck, lint, format, build green, 2950 passed and 2 skipped. One earlier full app run hit the known `vaultSearch.test.ts` timing flake (183 ms against 64 ms under load); it passes alone and on the rerun.

## Decisions

- CTO call: the restore notes are read from the journal rather than kept in a field, so each rides exactly one task and a restart does not lose them. A rewind takes back the preamble of the message it removes, so a note that rode that preamble comes back for the next task, which is right: the model no longer has it.
- CTO call: the marker gains an optional `kept` (additive): the files the journal saw change after the message that the rewind did not put back. Chat only, that is every file a later checkpoint or an Undo or Redo touched; with the files, only an Undo or Redo of an earlier task's change made after the message can leave one. The next preamble names both lists, so a chat-only rewind does not leave the model thinking its files are older than they are.
- CTO call: a checkpoint already fully undone is passed over; one partly undone is finished. A checkpoint missing from the store (aged out) is a failure, so the rewind stops rather than leaving a gap.
- CTO call: a rewind in progress counts as busy: no task starts (a send waits in the queue and runs after), no Undo lands, and the driver is not evicted.
- CTO call: `osc:rewind` asks main no second time, like `osc:restoreCheckpoint`: the sheet is the person's choice, and the channel reaches only this session's own checkpoints, the same reach Undo already has. The files go back only on an explicit `true`; the seq is a number in main and a safe integer in the host.
- CTO call: the app cuts at the first user item whose seq is at or after `toSeq`, never by counting items, so a phone that joined late or trimmed its oldest rows cuts at the same message.
- CX call: the files choice shows only when a later task has a checkpointed change card. Otherwise, and on every chat with no folder behind it (the phone's model, the Stack, a cloud key, the free chat), the one choice reads "Rewind chat", not "Rewind chat only", since there is no second option, and the files sentence is left out. The sheet never offers what cannot happen.
- CX call: a chat whose brain lives in the app is rewound in the app: the thread is cut and the brain rebuilt from what is left, the way a reopened chat's is. The guided setup's chat offers no rewind, since its walk is keyed to its lines.
- CX call: the title is "Rewind to this message?", the body "The chat goes back to just before this message, and your message returns to the box so you can change it.", then the ruled files sentence. The sheet stays up while it works (the tapped choice reads "Rewinding..."), says a refusal inline, and closes only on success.
- CX call: every device gets a quiet line: "Rewound to an earlier message." plus which files went back, or "The files stayed as they are."
- CX call: on the phone the hold takes the bubble's text selection (it would fire the iOS selection loupe at the same moment), so the sheet there adds "Copy message".
- Esc Esc: two presses within 700 ms in an empty, idle field. With a draft, the first Escape clears it as before and does not count. While a task runs, Escape still stops it.
- Haptics: `hapticTick` when the hold fires (the arm of a gesture, like a swipe row), `hapticCommit` on the choice. The held bubble eases down on the press tokens and springs back.

## What remains

- Device check (desktop, Mac and Windows): hover a sent message in a coding chat, see the round action, rewind with files; the files are back and `git status` shows only what the checkpoints put back. Esc Esc in an empty composer opens the same sheet for the last message.
- Device check (iPhone paired, reference box): long press a message, feel the tick, see no selection loupe; "Rewind chat and files" on a slow box; the desktop's chat folds the same way at once. "Copy message" copies.
- Files a checkpoint never held (gitignored, over 20 MB, a folder past 20,000 files) are not put back and not named in `kept`, since the journal never saw them (`os-code/src/daemon/session.ts`, `rewind`). The sheet's files sentence is true only for what the checkpoints hold.
- After a rewind the live agent's history is the coarse seed (each kept turn's words and final answer, no tool transcript), the same as a revived session. Truncating the live history at the matching turn instead needs a turn map in `os-code/src/core/agent/loop.ts`, which this wave did not touch.
- The per-card Redo goes with the cut cards, so there is no way back from a rewind in the app, though the shadow store keeps the redo snapshots (`os-code/src/core/checkpoints/shadowGit.ts`).
- Only the words return to the composer; a rewound message's attachments do not (`app/src/screens/ChatScreen.tsx`, the sheet's `onChoose`).
- When the rewound message has fallen out of the in-memory window (600 items), `rewindThread` finds no message at or after the seq and keeps the rows it holds (`app/src/state/rewindOps.ts`, `rewindThread`). A reopen replays correctly.
- The CLI (`os-code/src/tui/`) has no rewind command.
- `os-code/src/core/agent/bootstrap.ts` changed one line (the rehydrate seed reads `driver.replayJournal()`); P1 also edits this file, so the merge should keep both.
