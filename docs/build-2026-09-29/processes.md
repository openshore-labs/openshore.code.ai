# Build 2026-09-29, package P1 "processes": run my app

## Log

The agent can start a program that keeps running, read it later, and stop it (CTO wave-3 ruling P1). A new `os-code/src/core/tools/process.ts` holds `startProcess {command, readySeconds <= 30}` (risk `shell` with `commandOf`, so the lockdown ask, the wrapper rules and the code-flag refusals apply), `readProcess {runId, lines}` (read risk) and `stopProcess {runId}` (read risk, this agent's own runs only, no ask). They reach the session through a new `ToolContext.processes` seam that bootstrap wires to the driver: `startAgentProcess` holds the cap of three and calls `runCommand(cmd, {source: 'agent'})`, so each program is a run on the existing command lane (the same card, with Stop, on every host), started by the shared runner with the resolved shell and the scrubbed environment. `session.ts` keeps a rolling 64 KB tail per run (the runner keeps no whole copy for these, `retain: false`), notes the local addresses a program prints from whole lines, and wakes `startProcess`, which returns once the program prints an address or exits, or after `readySeconds` (default 10). The programs end when the session is disposed or evicted (a live one no longer holds a session from eviction), when the daemon closes, when the desktop quits (`engineHost.disposeAll`), and at process exit as a last net for the CLI; the card ends at once, so a revived journal never shows one running. The next turn's context line says "a process you started", and "stopped by the person" when the person pressed Stop. The tools register right after `gitCommit`, stay out of `SMALL_MODEL_TOOL_PRIORITY` (loop.ts untouched), and a lean seat's tools and system prompt are byte-identical with them on. Never on a headless run, in a member's session (the daemon passes `processes: false` for a member, on create and on revive), or in plan mode (a registry `when` gate read live, so they come back when the plan is approved). Config `tools.processes: 'on' | 'off'` (schema default on), classified off-only in `projectPolicy.ts`. `localAddresses` (pure, through `os-code/protocol`) finds loopback and wildcard addresses. App: the command card says "Started by OpenShore" for an agent run, and while a program runs, a local address becomes an "Open localhost:5173" link on the desktop on its own engine; the phone and a desktop driving another computer keep it as plain text. Terminal Control now governs `startProcess` like `runShell`, and under the secrets lockdown On shows the card rather than auto-approving. Tests: new `os-code/test/processTools.test.ts` (30: start and the early return, the split address, readySeconds, exit within the wait, scrubbed env, read and the 64 KB tail, own runs only, the cap, dispose, eviction, daemon close, the context line, registration order, headless, member, plan mode, config and project policy, lean menu byte-identical, lockdown ask, wrapper and code-flag rules, `localAddresses`), a member case in `os-code/test/daemon.test.ts`, new `app/test/commandCard.test.tsx` (9) and three cases in `app/test/terminalControl.test.ts`. Gates green: engine build, typecheck, lint, format, 131 files, 2082 passed and 2 skipped; app typecheck, lint, format, build, 214 files, 2938 passed and 2 skipped. One app run had a timing flake in `app/test/ethicsDriver.test.ts` (Tier 2 likeness) under load; it passes alone three times and in the next full run.

## Decisions

- CTO call: a live program the agent started no longer blocks eviction (`LocalDriver.evictable`); only a command the person ran does. Otherwise "killed when evicted" could never happen, and a dev server would run until the daemon quit.
- CTO call: the plan-mode rule lives in the registry, not the loop: `ToolRegistry.register(tool, {when})` hides a gated tool from `specs()`, `names()`, `all()` and `get()` while `when` says no, and bootstrap reads the agent's live mode. A call to a hidden tool finds no tool. loop.ts is untouched.
- CTO call: `buildToolRegistry` registers the three only when asked (`processes: true`), since only a host with a driver can hold a program; the eval harness and hand-built test sessions are unchanged. Bootstrap asks unless the run is headless, the session is a member's, or config turns them off.
- CTO call: `stopProcess` is read risk, the one class that runs without asking by default, since it only ends what the agent itself started.
- CTO call: Terminal Control governs `startProcess` (`SHELL_TOOLS` in `app/src/lib/terminalControl.ts`), since starting an app runs a command the model wrote; otherwise Off would have a way around it. With it included, On would have auto-approved under the secrets lockdown, so a lockdown request now shows the card with On (this also closes the same gap for `runShell`, where the engine asked but the app answered yes).
- CTO call: on dispose, eviction and shutdown the card's `command-end` is emitted at once (exit null, SIGTERM), because a closing host may not live to see the exit and a revived session would show a spinner forever.
- CTO call: a process-exit hook in `session.ts` stops any live agent program, the last net for a host that exits without disposing (the CLI); each run is its own process group and would outlive OpenShore.
- CTO call: agent programs keep stdin as a pipe, like the person's commands, since some watchers exit when stdin closes.
- CTO call: `startProcess` returns early on the first local address or on exit; addresses are read from whole lines, so an address split between two chunks is never taken for a shorter one.
- CTO call: the schema fills `tools.processes: 'on'`, so a project's `'on'` from an untrusted folder is a no-op, never a spurious trust card; over a machine that says `'off'` it waits for trust ("lets the agent start programs that keep running, like your app").
- CTO call: a session keeps its five most recent ended programs for a last read, so a long day holds a bounded amount of output.
- CX call: the Open link shows only while the program runs (after it ends nothing serves there), reads "Open localhost:5173" (the address without its scheme), and a wildcard bind (`0.0.0.0`, `[::]`) opens as localhost, since `python3 -m http.server` prints 0.0.0.0 and a browser on Windows cannot open it. It applies to a command the person ran too.
- CX call: tool labels "Start a program that keeps running", "Read what a program printed" and "Stop a program" (`app/src/lib/toolVerbs.ts`), and transcript rows "Start: {command}", "Read a program's output", "Stop a program".

## What remains

- `os-code/src/core/agent/loop.ts:2077` (`noteRepeat`): a second identical `readProcess` call with nothing changed in between is answered as stale ("Nothing has changed since"), though a live program's output moves. The loop's owner could exempt tools whose result depends on time, or count a `startProcess` run's output as a change.
- A lean (tiny or small) seat never sees these tools by design, so on a small local model "run my app" still reaches `runShell` and waits out its 120 s timeout. A one-line lean-prompt hint would change the lean prompt and needs an eval number first. `os-code/src/core/tools/runShell.ts:11` still says `bash -c`.
- The card's journaled output stops at 64 KB per run (`os-code/src/daemon/session.ts:1127`, `COMMAND_EMIT_CAP`), so a chatty dev server's card shows "Output truncated." while `readProcess` keeps the rolling tail. A rolling card for agent runs needs a replace-tail event.
- `osc serve` exits right after `close()` (`os-code/src/commands/serve.ts:43`), so a program that ignores SIGTERM never gets the SIGKILL the grace timer would send. The same holds for the desktop quit.
- A command the person ran (`source: 'user'`) still keeps its whole output in memory and is not stopped when the daemon closes (`os-code/src/daemon/session.ts:1138`, `os-code/src/daemon/serve.ts:1705` stops only agent programs). This was the case before this package.
- The Windows path is not run here: the first `windows-latest` run proves the start, the tail and `taskkill /T /F` on Stop. The tests use `node <file>`, so they run the same under Git Bash and PowerShell.
- Device checks a person must do: on the Mac, open a Vite or Next project with a mid or large seat, turn on Terminal Control, ask "run my app": the card says "Started by OpenShore", "Open localhost:5173" opens the browser, the model's reply names the address, Stop ends it (`lsof -i :5173` is empty), and quitting the app leaves nothing listening. With Terminal Control off, the model says to turn it on. With Tokens and Secrets on, the approval card shows for the start with Terminal Control on. On the paired phone the same card shows the address as plain text with no link, and Stop works; leave the chat untouched for 30 minutes with the phone closed and the server is gone. In `osc run`, start a server, then quit: nothing is left listening. On Windows, start and stop a server with and without Git Bash.
