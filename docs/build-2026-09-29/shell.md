## Decisions

- CTO call: the child environment is a denylist by name convention, not an allowlist. Toolchains read dozens of variables (JAVA_HOME, NVM_DIR, PYENV_ROOT) and an allowlist would break builds a person cannot diagnose; an interactive terminal still sources the person's own shell files, so what they export there is theirs.
- The provider reads the environment first and the store second, as the build doc words it, and only for `OPENAI_API_KEY`: a config naming any other variable never reads an unrelated credential out of the store.
- CTO call: a paired coding CLI keeps only its own key through the scrub (`keepEnv`: `ANTHROPIC_API_KEY` for Claude Code, `OPENAI_API_KEY` for Codex), for a person who signs it in with an exported key. Every other command gets the scrubbed environment.
- The Linux pipe-to-shell is removed rather than put behind `confirmInMain` (item 7's first option): the renderer never called it, and a download piped into `sh` with sudo is not made safe by a dialog. The terminal-mode confirm in item 6 therefore has nothing left to guard; Linux returns the command with `started: false`.
- CTO call: `confirmInMain` defaults to Cancel. A page that fires the IPC while the person is typing must not have their next Enter confirm it.
- Launch at login asks only when turning on; turning it off only removes persistence.
- A command or keystroke refused for focus returns the answer for a session that is gone (`undefined`, `false`), so the bridge types and the renderer are unchanged.
- `dir()` also refuses ancestors of home and a parent of a relocated settings folder, matching the vault chooser; it returns the realpath, so a session's cwd is the real folder.
- The `terminal-opened` audit marker is emitted once per shell started, not per reattach.
- The daemon kills only terminals it created on close; a manager handed in (tests, a future shared one) is its owner's to end.
- Desktop dictation and voice mode listen through the web speech engine, so the app's own page keeps microphone audio; camera, location, notifications and opening other apps by link are always refused.
- The sign-in listener requires the state on a refusal too, so a stray local request cannot end a sign-in in progress; comparing the state stays in the renderer.
- A background update check that fails is its own event (`check-failed`) so an offered update is not turned into "failed" by an offline minute; a retry waiting on its check does fail with it.
- Windows ends the tree with `taskkill /T /F` on both the first step and the grace step (console programs ignore a polite close), keeping the timer.
- Shell wrappers match by lowercase, without `.exe`, and by path basename, since PowerShell, cmd and a Mac's disk ignore case and `/bin/sh` is still `sh`.
- The Ollama installer's temp folder is removed on failure and kept after success, since the opened installer lives in it.
