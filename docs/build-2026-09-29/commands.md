## Decisions

- CTO call: a repository's commands folder must resolve inside the workspace, so `.claude/commands` linked to a folder elsewhere is refused whole and reported. The person's own folders may be links (dotfiles are often kept that way); the per-file rule still applies to them.
- CTO call: the frontmatter is read line by line, not as YAML. Claude Code's own documented `argument-hint: [pr-number] [priority]` is invalid YAML, and the hint is shown exactly as written.
- CTO call: a `!` line is any line that starts with `!` (a markdown image `![...]` excepted) plus Claude Code's inline !`cmd`. The file's lines are read for these before the person's arguments go in, so text the person typed is never taken for one. The model reads "not run" in the text and a line saying it may run what it needs with its own tools, which go through the usual permission path.
- CTO call: `commands` rides `repo-info` only when the list changes (absent means unchanged, clients keep the last one), so a busy session does not journal the list twice per task. A folder with commands emits one `repo-info` as the agent attaches, so the menu and the terminal list them before the first task; a folder with none emits nothing new, leaving every existing event stream as it was.
- CTO call: the loser report rides `repo-info` as `commandsNotLoaded` with a reason code, and one pure function words it for both surfaces. The terminal's `/help` lists every one; the composer says the one whose name the person is typing, under the rows (a disabled option, so the listbox stays valid).
- CX call: the person's own commands are labeled "From your computer"; the ruling's "From this repository" marks the repository's. On a paired phone the command lives on the desktop, which is what "your computer" means everywhere else in the app.
- CX call: a picked command with an argument hint fills the field for the argument; one without runs at once, the same rule the built-ins follow.
- CTO call: names are lowercase (letters, digits, `-`, `_`, up to 64); subfolders are read three deep and a command keeps its file's own name (Claude Code's namespacing); within a tier the first folder in the ruling's order wins and the rest are reported. A skill is named after its folder.
- CTO call: the 200-file cap counts across every folder in order, so the repository's are looked at first; once reached, nothing more is read and one "too many" line is reported.
- CTO call: commands load without folder trust. A command file only adds text to a task the person started, its tool and model keys are never read into anything, and the permission path judges every step as before; `projectTrust.test.ts` pins it.
- CTO call: the two notes land right after `task-start` (the driver's `emit` flushes them), so they sit under the person's message instead of above it, with no edit to `loop.ts`.
- `CLAUDE_CONFIG_DIR` is honored for Claude Code's folder (its own variable; the eval baseline already sets it), and the engine test setup points it at a temp folder so no test reads the commands of whoever runs the suite.
- No new config key, AppSettings key, room, or host.
