## Decisions

- CTO call: build-time `SHIPS_*` constants beside `featureOn`, not a Vite plugin or a `define`. Rolldown never folds a call, so `featureOn('x')` keeps a later tier's strings in the bundle; a `define` would freeze the tier for the suite, which reloads modules at tier 1 (`tierPersonal.test.ts`). `focus.test.ts` reloads every tier and holds each constant to `featureOn`.
- CTO call: the later rooms' `import()` gates are written in `App.tsx` itself. Rolldown decides which chunks a module emits before it inlines another module's constants (measured: a gate imported from focus.ts drops the call but still emits the chunk), so only a literal in the importing file keeps the chunk out. `tierBundle.test.ts` pins the gates to `ROOM_FEATURE` and `FEATURE_TIER`.
- CTO call: the bundle check runs in CI on the build CI makes, not inside vitest. Running `vite build` inside the suite took 3 to 5 s alone but starved the parallel workers (a `tierPersonal` test hit its 5 s timeout once); the suite proves the checker on a fixture instead.
- CTO call: at tier 1 the Agentic and Harness Currents rosters are empty. Nothing reaches them in a Personal build (`agenticView`, `harnessView` and `refreshCurrents` already shut), and it is the only way their names leave the bundle.
- CTO call: the driver's one reference to the Jev advisor (`stackDriver.ts:568`) and the Codemagic tool handler (`codemagicTool.ts`) got a `SHIPS_*` gate. It is one line in a driver, no behavior change at any tier, and the brief's "cut those references" covers it.
- CTO call: ChatScreen and OnboardingScreen stay in the first chunk (home and first run are on screen at launch); every other room warms 1.5 s after launch, one at a time, so the first open of a room waits on nothing.
- CX (ruling 9.2): Run on another computer does not accept the one-time pairing code, and the integrator said not to build that flow, so its field reads "Access key".
- CX (ruling 9.5): the excerpt line reads "Takes about N% of this model's room" when the window is known, else "About N words" counted from the text; the pins line (same helper) follows.
- CX (ruling 9.3): the hardware words ("16 GB memory, no graphics card") changed in `firstSeat.ts hardwareDesc`, which the First Seat fit line also uses.
- The sign-in password field's placeholder reads "At least 8 characters" when creating an account (the label now says Password).
- Deleting the Coming soon path and the paywall intercept means a tier-3 build opens the Local Library directly; that is the tier rule's intent (unlocking a tier is the founder's call).
- Field ids are static strings where the form renders once (the `vault-rename-name` precedent); `SignInCard` uses `useId` because it can sit in more than one sheet.
