The first `windows-latest` run (CI run 36543782677, job 109325171841, step "Test the engine", the whole 3,198-line log read) had 76 failing engine tests in 15 files; the app's Electron-side step never ran. Every one now has a cause and a fix, listed below so the next Windows run can be checked against it. Product fixes, each with a test that runs on every OS: the outbox's path confinement resolves the root before comparing (`os-code/src/git/outbox.ts`, `confinedPath`), since git on Windows answers `--show-toplevel` with forward slashes and the raw prefix check refused every path; the command runner reports a run it stopped as stopped on every system, no exit code and the signal it sent (`os-code/src/core/exec/commandRunner.ts`), since Windows' `taskkill /F` leaves exit code 1 and the card read "exit 1" as a failure, and the session names a person's Stop from what the run knows (`os-code/src/daemon/session.ts`); `vaultWrite` never treats a name Windows cannot hold as an existing note there (`os-code/src/core/tools/vault.ts`, new `windowsCanHold` in `os-code/src/harness/vault/paths.ts`), since a colon names an NTFS stream and `CON` the console; the app's folder checks judge with the separator and disk tops of the platform they are told (`app/electron/vaultDir.ts` `within`, new `isDiskTop`, used by `mainGuards.ts`); the XDG autostart path is composed with POSIX separators (`app/electron/lifecycle.ts`). Test fixes, no assertion loosened: one helper, `os-code/test/helpers/portable.ts`, moves HOME and USERPROFILE together (`os.homedir()` reads USERPROFILE on Windows), removes a temp folder with a bounded wait while Windows still holds it, and retries a random port that Windows reserved (EACCES); separator-neutral expectations in `daemon`, `daemonVault`, `evalV2` and `outbox`; `shellHost` reads PATH by any case. ## Decisions

- CTO call: HOME is a test harness bug, not a product one. `os.homedir()` is the right product call (USERPROFILE on Windows, HOME elsewhere); the tests moved only HOME, and restored an unset HOME as the string "undefined". One helper moves and restores both exactly.
- CTO call: the EBUSY cleanups are not a leak. The processes an agent starts are ended with the whole tree (`taskkill /T /F`) at dispose, eviction and daemon close, and the git status after a task ends by itself in milliseconds; Windows only lets go of the folder a moment later. `dispose()` stays synchronous (eviction and quit call it); the tests wait for the folder, at most five seconds and only on the codes Windows answers with meanwhile, so a real leak still fails.
- CTO call: vault names. An existing note keeps any name its file system gave it (Vault M3, H4), but on Windows a name the file system cannot hold is never a note: a colon names an NTFS stream of another file, so a write would hide text inside `Decision`, and `CON` opens the console. On Windows such a path goes to the one new-name rule, which refuses it with the clean name, the same words a new note gets on every system; a Mac's note by that name never reaches a Windows folder as a file. The POSIX update case keeps running on macOS and Linux.
- CTO call: a stopped run is stopped on every system (runner), not only on Windows. A POSIX program that catches SIGTERM and exits 0 used to read as "exit 0" after a Stop; it now reads as stopped, which is what happened. runShell and cliAgent judge a timeout or an abort by their own flags, never the exit code, so nothing else moves.
- The noteFile rename race is a POSIX race: Windows refuses the rename while the read's handle is open, so the case cannot happen there. Skipped with the reason rather than rewritten, and the Windows race (an in-place save) got its own test.
- `within` in the app honors the platform it is given for the separator and the disk top, not only for case. Production passes `process.platform`, so nothing changes on a real machine; the checks can now be tested for any platform on any host.
- Test platform switch: the Windows refusal test sets `process.platform` to win32 for the call, the pattern `noteFile.test.ts` already uses, so it proves the gate on Linux and runs as itself on Windows.
