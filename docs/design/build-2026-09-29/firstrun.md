## Decisions

- CTO call: the free chat function yields an `open` event once every check has passed, and the daemon writes and flushes the SSE headers then, so a phone knows at once that the answer is on its way (a local model can be slow to its first word). A refusal is one `refused` event carrying the HTTP status, so the daemon still answers 400, 409 and 413 before any header.
- CTO call: the daemon's abort now listens on the response's `close`, not the request's. The request's `close` has already fired once `readJson` read the body, so a phone's Stop never reached the model and the H1 lane stayed busy (409) until the model finished. `daemonLifecycle.test.ts` fails on the old signal.
- CTO call: the desktop's IPC free chat builds no vault pack, signed in or out. Signed out it must not (ruling 8); signed in, the agent and the Stack carry notes, and a pack in main needs the owner's root and privacy holder. `freeChat` takes an optional `pack` builder, so adding it later is one argument.
- CTO call: the desktop window has one lane of its own (`'window'`), apart from the daemon's per-credential lanes, the same one-at-a-time rule a paired phone gets. A reload stops every answer still running (`did-finish-load`), and so does quitting.
- CTO call: the free chat's system line now reads "running as read-only chat with the person's own local model" instead of "over a phone-to-desktop link", since the desktop's own window uses it too. The tests' `desktopChatSystem` import still works through a re-export from `serve.ts`.
- CTO call: on the desktop, `desktop-chat` is ready only with a local orchestrator (`engineChatReady`), since the engine refuses one that leaves the network; `desktop` readiness is unchanged.
- CX call: the waiting message is sent on the composer's default at that moment: the free chat signed out, the agent signed in (what the person would have got had the model been ready). If something other than the engine can answer first (a cloud key, a Stack built meanwhile), the words go back into the composer rather than to a model the card did not promise.
- CX call: a second send while one waits joins it, after a blank line, so both go and nothing is dropped.
- CX call: the sign-in line shows while DeepBlue downloads for anyone signed out, with or without a waiting message, since the download is the dead time either way.
- CX call: the desktop keeps the Local models row and makes it honest (the free chat, or the Stack link naming DeepBlue) rather than hiding it, because the out-of-usage "Switch to a local model" opens that stage directly.
- CX call: the parked bubble arrives after one second (`.msg-parked`, a delay the motion guard allows), so a chat whose brain takes the message at once never shows "Waiting to send" on the way.
- A waiting message that cannot open a chat after all (a door in the way) is held again for the composer, never dropped.
- `SOURCE_ACCOUNT` in `accountGate.ts` makes a new source kind a type error until classified; `codingLocked` and `newConversation` read it.
- The gate note's `terminalStdin` half was left alone: the task named `runCommand`, and the terminal room is already behind its own door.
