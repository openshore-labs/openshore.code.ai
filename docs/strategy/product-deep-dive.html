02 Local models · the brains

Your stack: one quarterback, specialists on the bench.

OpenShore is not one model, it is a stack you assemble. One reasoning model runs the show and routes every task. Specialists plug in by role. Anything you have not placed, the quarterback covers itself. It is the piece that makes "bring your own model" into a coherent product rather than a model picker.

The quarterback and the bench

Shipped

A required Reasoning LLM anchor plus a bench of models you place into industry-standard roles: coding, writing, analysis, vision, embedding, fast. Each placement can carry a trigger ("when called") and a custom persona. The router sends each turn to the reachable specialist for the job, and degrades gracefully: if a specialist cannot run, it falls back to the anchor instead of dead-ending. A single-model setup is a fully supported path, and the engine only ever shows tools the stack can actually serve.

At full strength The turn classifier, a keyword heuristic today, becomes a real Harbor Mini classification call, and specialists gain tool use and multi-step delegation on the phone side, closing the gap between the desktop engine's routing and the pocket router.

Bring your own model

Shipped

Connect any OpenAI-compatible endpoint you control, a self-hosted vLLM or Ollama, a fine-tune behind your gateway, another provider. Name, base URL, model id, optional key. The key lives in the device secret store, scoped, never synced. It lands on the bench and places like any other model, and a box-hosted endpoint can be driven through the daemon.

At full strength True streaming and cancel for BYOM endpoints on iPhone and desktop (buffer-then-dump today), via native IPC and SSE bridges.

Cloud, only when you say so

Shipped

Add Claude, OpenAI, or Gemini on your own key; their models join the bench. The agent can offer to escalate to cloud after repeated local failures, but never spends without a confirm sheet that shows a cost estimate and the session total, in amber so it never reads as a free local turn. With no key connected, escalation simply reads as off, so you are never asked to approve spend that would error.

Harbor and Harbor Mini

Shipped

Two built-in on-device guides so the app is useful the instant it opens. Harbor Mini (Qwen2.5-0.5B, ~380 MB) seeds a fresh stack and keeps first-run small. Harbor (Qwen3-1.7B, ~1.1 GB) reasons and does real web search on-device via a one-line protocol, with citations. Both are honest: not coders, they point you to a real model for real work. Weights pull straight from Hugging Face, never from OpenShore.

At full strength Harbor Mini graduates from guide to the stack's routing brain, classifying every turn.

Mid-chat switching, effort, and mode

Shipped

Change the model mid-thread and keep the conversation (Claude-style reseed, only when idle). A reasoning-effort selector rides into every turn. The three permission modes (Auto, Accept edits, Plan) govern how the agent's tool approvals flow. All from the composer, without leaving the chat.

03 The agent · the making

A real coding agent, tuned to survive on local models.

The engine is a streaming ReAct loop in the familiar shape of a modern coding agent: it reads, edits, runs, searches, and commits, feeding each result back until the work is done. The hard part, and where most of the engineering went, is making that reliable on small local models that are not as forgiving as a frontier cloud model.

The toolset

Shipped

Read (numbered, sliced), write, edit, glob, and grep (ripgrep with a pure-JS fallback); a default-deny shell with per-command approval; git status/diff/commit; web search and fetch (readable markdown, egress-checked); delegate to a specialist; analyze and generate images; semantic repo search; and a read-only view of your live terminal. Every tool validates its arguments, declares a risk class, and caps its output.

The edit engine

Shipped

Edits arrive as search/replace blocks and land through a deliberate match hierarchy: exact, then whitespace-tolerant, then context-anchored fuzzy, applied only when the anchors are unique. Any ambiguity is refused with a teaching error that names the closest line and counts duplicates, because a tolerant matcher landing a hunk in the wrong place is silent corruption. Every apply is diffed and verified before it returns.

The tool-call bridge

Shipped

The make-or-break piece for local models. The loop accepts native tool calls and a JSON-in-text fallback, with a fence-aware, string-aware extractor and a bounded repair pass that fixes the things small models get wrong: smart quotes, Python literals, trailing commas, unquoted keys, unbalanced braces. Backends that support it get a grammar-constrained retry; persistent failures draw a corrective prompt, then an offer to escalate. Per-family prompt adapters (qwen, llama, generic) tune preamble, stop tokens, and tool format per model. This is the difference between "local models sort of work" and a real agent on your own hardware.

Approvals, spend, and guardrails

Shipped

Reads flow; writes ask with a diff; shell asks with the exact command; cloud spend gets its own amber confirm. Session-wide "always allow" is profile-gated, and knowledge-base writes are always-ask no matter what. Hard stops bound every run: max steps, repeated-call loop detection, wall-clock, token, and dollar budgets, each halting with a plain sentence rather than a runaway.

Repo awareness

Shipped

An incremental embedding index (with a keyword fallback when no embedder is present) powers semantic repo search, and a compact code map, a tree plus a regex symbol outline across seven languages, is injected into the prompt so the first tool call is aimed right. Older turns compact automatically to keep small context windows honest.

At full strength The symbol map moves from regex to a tree-sitter parser behind the existing seam, and MCP-stdio plus checkpoints and rewind land for full Claude Code parity.

04 Desk to pocket · the reach

Your machine does the work, your phone carries it.

The standing principle: long or agentic work runs off the phone, on your own daemon, as a durable, journaled, resumable job, because iOS grants no app minutes-long background compute. The phone is a remote control and a viewer, so a long answer keeps going when you put it in your pocket. This is the piece that behaves like Claude Code, on hardware you own.

Pairing, the celebrated first run

Shipped

Turn on the desktop daemon, scan a QR from the phone, done. Everything runs over your own Tailscale network; the daemon binds Tailscale or loopback, never 0.0.0.0, behind a bearer token, and every paired device gets its own revocable credential. Onboarding leads with "Connect your computer" because that is the value: your machine does the work, nothing drains the phone, nothing gets cut off in the background.

Box-run, and it survives the subway

Shipped

Pick your computer's stack from the phone and the agent runs on the machine, streamed to your hand. Every event is journaled and replayable from any sequence number, so a tunnel or a locked screen costs nothing: the phone reconnects with backoff, resumes from the last event, and drops a single "connection blipped" row. The generation lives on the daemon, not in an app process that iOS would suspend.

A real terminal, reattaching

Shipped

A full PTY on the desktop, rendered on the phone with xterm.js over the same connection. Colors, cursor addressing, sudo, vim. The PTY outlives the screen (tmux-like) and replays its ring buffer from the last byte on reconnect. An iOS accessory key row adds Esc, Tab, Ctrl, arrows, and pipe. No Termius, no screenshots.

Models on the phone itself

Shipped

A native plugin runs GGUF models on-device via llama.cpp on Metal: load, stream, stop, with resumable background downloads that adopt on relaunch and a background assertion so an in-flight reply is not killed the instant you glance away. This is the offline half of the stack, and the engine behind both guides.

Voice, on-device only

Shipped

Dictation through a native plugin with on-device recognition forced on, so mic audio never leaves the phone; it reports unavailable rather than quietly falling back to Apple's servers, and handles call and Siri interruptions. The web build falls through to the Web Speech API.

It taps you when it needs you

Shipped

When a desktop run needs your input and no phone is watching, the daemon sends a content-free "session needs you" push. While you are watching, it holds the banner back. The push grant is opaque and server-minted, held sealed at rest.

At full strength A hosted cloud runner joins the desktop daemon as a second off-device home, so long jobs can run even when your own machine is off.

05 You own it · the substrate

Repositories: your code lives where you choose, not on someone’s servers.

This is the piece no rival in the sovereign-agent cohort has. Underneath Repositories and Vault sits gitOS, one storage seam that hands the file store back to you: a repo or a vault is a named tree of bytes that live where you chose, and everything above the seam reads through it without ever learning the backend. It extends sovereignty from your compute to your data.

The gitOS storage seam

Shipped Backends expanding

One path-and-bytes interface (list, read, write, remove, plus a single-writer lease) that Vault and repos share. Live backends: Local (sealed on the device), a plain on-disk folder that Obsidian opens directly, iCloud Drive (native plugin, synced by iOS), and Google Drive (real OAuth PKCE, drive.file scope only, a real folder tree you can find in Drive). Secrets on untrusted storage seal under a per-repo key, never the device key, so the cloud provider never sees plaintext. Not-yet-wired backends render honestly as "Arriving," never faked.

At full strength Dropbox and Proton Drive providers wire up, real git shells out on the desktop engine for true branch and merge semantics, and the per-repo secrets model completes. The seam was designed so each new home is an additive plugin, not a rewrite.

Connect and build a repo

Shipped

Connect GitHub or another platform on your own token (kept in the device keychain). Clone from a URL, or open a local folder on the desktop, and either opens a coding chat that reads, edits, tests, and commits with per-change approval. A recent-workspaces list gets you back in fast.

The offline commit outbox

Partial · flag-gated

A pipeline that lets the phone author commits offline: intents are sealed on-device, then materialized into real commits by git plumbing without ever touching the live working tree, idempotent, with conflicts landing on a rescue branch and never a force-push. Built and tested end to end on the desktop engine, held behind a flag until the app flow that produces buffered intents ships.

At full strength The producer and home-path picker flip the outbox on, and platform remotes (GitHub, GitLab) gain a real push path so "your own GitHub, hosted where you like" is complete.

05b You own it · your knowledge

Vault: an Obsidian-compatible knowledge base, on the same owned storage.

The first thing built on the gitOS seam, and proof the seam is real. Your notes are plain markdown files you can walk away with, in OpenShore's own paper-and-ink theme, that the agent can read and (with approval) write.

Personal Vault

Shipped

Folders of .md files with live [[wikilinks]] (autocomplete, create-on-link), read/edit toggle, linked mentions (backlinks), and Obsidian-style save-as-you-type that flushes on background and switch so nothing is lost. A "where it lives" sheet moves the whole vault between storage backends. Export to real files in the iOS Files app, and point Obsidian at the same folder, it just opens. A single-writer lease makes a note read-only when another device holds it. Your notes are device property: they survive signing out, like your on-device model files. The agent's vault writes are always-ask, never silent.

At full strength The Team Vault, a real multi-writer backend (last-write-wins with conflict copies, not a naive folder sync) so a company can share one knowledge base with genuine concurrent editing. The Supabase backend exists; hardening it into the organization tier is the one tracked open follow-up.

05c You own it · your workflow

Projects keep the context. Crew makes the agents yours.

Two features that turn a chat tool into a way of working. Both persist to the account, so your setup is yours across devices.

Projects

Shipped

Buckets that hold chats and their context. Standing instructions ride into every chat in the project, and repositories can be shared across projects. Switch the active project from the sidebar. Deleting a project keeps its chats, they just lose the link.

My Crew

Shipped Auto-invocation partial

Build your own agents, each with a name, a persona, and a call rule, scoped to specific projects or all of them. Three activity levels: Reviews builds (runs before a deploy), Auto-reasoning (the quarterback can bring it in on its own), and Request only (dormant until named). Personas are woven into the router's prompt as your own authored perspectives.

06 Ship it · the finish

Launch: from a working build to the App Store, without leaving the app.

This is the capstone that closes the loop, and the piece the whole sovereign-agent cohort lacks. Every other tool hands you code and stops. OpenShore walks the last mile to a release.

Ship to the stores, guided

Shipped

One place to get a built app onto the App Store or Google Play through Codemagic, guided from inside OpenShore. A "guide me" button spins up a stack chat that walks every account and setting. Connect a Codemagic token (kept in the keychain), set a target (platform, app id, workflow, branch), and build: the app triggers Codemagic, follows the build over its API, and on failure reads the redacted log so the model hands you a fix, not a wall of logs. If you have review-level crew, they can vet the build first. Idea to shipped app, and the code never left your machines to get there.

At full strength More build targets and platforms, and the review-before-deploy hook fully wired to your named crew, so a failing build comes back as a proposed change rather than a report.

◆ Why the arc is the moat

Everyone else owns a slice. OpenShore owns the loop.

A small, fast wave of 2026 tools is racing for the same "sovereign, cross-device" corner. Reading them against this arc shows exactly where OpenShore is different, and it is not the idea, it is the depth.

  • Paseo (15k+ stars) nails the control plane: a private daemon you drive from any device. But it orchestrates other agents whose models are usually cloud. It owns the remote, not the brains, and it has no owned storage, no vault, no ship step.
  • OpenMono is the near-twin on thesis, a local-LLM coding agent with a phone companion, but it is a terminal tool and a marketing funnel for a bootcamp, not a finished product. No native app, no owned-storage seam, no launch.
  • The local runners (Ollama, Jan, LM Studio) own your compute but stop at chat. The cloud agents (Cursor, Copilot, Claude Code) own the polish but rent the brains and never leave the desk.

The difference is the whole arc. OpenShore is the only one that owns every step from idea to shipped app: local brains, a real agent, storage you control, desk-to-pocket reach, and a launch button, with the code never leaving your machines. Each rival can copy one box on the strip. Becoming the whole strip, native and finished, is the thing none of them can do without becoming a different company. The moat is not "local AI." It is the closed loop, executed to product finish.

An App-Store-style storefront for picking models in plain language, built on a strict honesty posture. OpenShore never rehosts or proxies weights: they download straight from Hugging Face or Ollama, and licenses are shown before you pull.

+ The guarantee · private by construction

Privacy is not a setting here. It is how the thing is built.

Every claim in this section is enforced in code and, where it can be, measured on your machine rather than asserted. This is the structural difference from tools that keep your code local by policy.

The security posture, in full

Shipped
  • Nothing leaves by default. Local models run the work; cloud is a manual, spend-confirmed flip on your own key, and OpenShore never routes to the cloud on its own.
  • The daemon is locked down. Bearer token on every request, per-device revocable credentials, binds Tailscale or loopback but never 0.0.0.0, and refuses to start otherwise.
  • Path jail and symlink escape refusal on every file operation; the vault has its own jail.
  • Secret redaction scrubs API keys, tokens, JWTs, and private keys before anything reaches a transcript, log, journal, or model, quote-safe so it never corrupts JSON.
  • Egress policy checks every outbound request by purpose and re-checks every redirect hop, so an allowed URL cannot redirect into a blocked host.
  • Encrypted at rest. Chats, projects, crew, journals, and vault sealed with AES-256, the key in the device secure store; credentials on untrusted cloud storage seal under a per-repo key the provider never holds.
  • Stricter on the phone. Three tightening profiles (local, remote-attached, headless); remote is always more restrictive than at the desk.
  • No telemetry, no analytics, no phone-home, ever. The only activity log is opt-in and local-only, and never sent unless you copy it out yourself.

At full strength An encrypted, per-account vault at rest for shared devices, and server-enforced roles once accounts move fully to the cloud (client-enforced today), closing the last gaps a hostile local user could reach.
