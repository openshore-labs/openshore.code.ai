# The advisor team on the v1 direction: the eight memos (2026-09-25)

The founder received advice setting the direction for OpenShore v1 ("Your
models, your keys, your machine, everywhere you go, and no one, including us,
is watching") and asked the team for a consensus go or no-go that closes the
gap on what v1 needs, with nothing built. Each advisor (the personas in
`uki-audio/.claude/agents`, serving OpenShore here) read the direction, the
facts the orchestrator had verified in code, PROGRESS, DECISIONS, the Zed
proposal, research, and memos, and the code their role needed, then wrote
independently. The memos are recorded here, condensed but faithful. The
consensus is `v1-direction-review.md`; the direction itself is quoted in full
at the end of that document.

All eight returned GO WITH CONDITIONS.

## CTO

**Verdict.** GO WITH CONDITIONS. The direction is right, but as written its own definition of done cannot be recorded: the phone cannot run the check or undo a change, and "no one, including us" is false in the code today.

**Conditions.**

1. Phase 1 must name "check and undo from the phone." Fact 1 holds: verify is skipped whenever shell cannot auto-run (os-code/src/core/agent/loop.ts:341), and every daemon session runs on remote-attached (os-code/src/daemon/serve.ts:966, :1239). Smallest correct fix: the machine trust store from Phase 0 holds exact verify grants, keyed by real path, origin, and a hash of the command. The owner grants one once, from either device, through the existing approval card; members cannot grant; a changed command asks again; shell still asks every time. Make verify async first: its execSync (os-code/src/harness/verify.ts:65) runs in the Electron main process, which also hosts the daemon (app/electron/engineHost.ts:900), so a long test freezes the window and the phone's 4-second probe (app/src/drivers/remoteDriver.ts:115) then reports "Can't reach your computer." Undo has no daemon route: add restore and redo, refused while the session is busy, journaled so both devices see them.
2. Move the ethics upload into Phase 0. Fact 2 holds and is understated: app/src/lib/ethics.ts:116-140 also uploads allowed likeness records that carry the named person (os-code/src/core/ethics/chokepoint.ts:65, :168), and buying Personal requires signing in. Keep the screening on the device; move the upload and the ladder into the team build, with a DECISIONS supersede line.
3. "Local by address" must mean loopback, LAN, or the person's own tailnet. os-code/src/core/security/egress.ts:58 treats any *.ts.net host as local, including a stranger's public Funnel host. That is the key-theft vector Phase 0 exists to close.
4. The hide flag is build-time and stops code from running. A remote switch would be a phone-home and an App Review 2.3.1 risk. Today the routine scheduler starts on its own (os-code/src/routines/scheduler.ts:189), and every launch probes saved Currents connections (app/src/state/store.ts:3391).
5. Settle the floor model in Phase 0: run qwen3:4b on the reference box on a fix-a-failing-test task. The deep suite has no such task (os-code/PROGRESS.md:220).

**Phase by phase.**

- Phase 0: trust first is right; add conditions 2, 3, and 5. num_ctx must stay the same for every call to a model and feed compactAtContextFraction (os-code/src/harness/profile.ts:78). A BYOM seat on Ollama's /v1 cannot carry it (app/src/drivers/stackDriver.ts:1171), so detect Ollama and use its native API. About 6 to 7 days.
- Phase 1: the loop's touched map (loop.ts:209) is not undo: it misses files a command wrote and is lost when the process ends. Use a shadow git directory outside the project, which works without git and is never pushed. Missing: the desktop first run (the guided walk is phone-only, store.ts:5776); pairing failures beyond the two the app names (remoteDriver.ts:147-152): phone and desktop on different Tailscale accounts, the Windows firewall, Ollama installed but stopped, a full disk mid-download, a sleeping desktop. Order: undo, verify, the hide flag, then first run, so strangers test the surface v1 will ship. About 12 to 16 days, plus a device pass on all three desktop systems.
- Phase 2: the egress audit before the copy, so the copy matches it. By default, with no tap: update checks to GitHub every 30 minutes with no way to turn them off (app/electron/main.ts:1106); the daily catalog fetch from openshore.ai (os-code/src/market/catalog.ts:52); DuckDuckGo for any local model's search (app/src/lib/webSearch.ts:71); probably spellcheck dictionary downloads on Linux, since spellcheck is on (main.ts:605). Once signed in: auth, entitlements, guardrail_events, and push metadata through our push-send (os-code/src/daemon/push.ts:211). On use: model downloads, the Ollama installer, git, Drive, Codemagic, Jev, Hermes, reviews, Tailscale's coordination server; cloud providers called with raw fetch that skips EgressPolicy (providers/anthropic.ts:160, openaiCompatible.ts:396); repo OAuth, whose code exchange runs on our edge function, so the person's token passes through our server (supabase/functions/repo-oauth/index.ts:206). False today as literally stated: "including us" (guardrail_events, push-send, the catalog, repo OAuth); "no phone-home" (the catalog and the update checks). What the test hooks: on the desktop, net and tls connect plus dns.lookup in the engine and Electron main-process suites, session.webRequest for Chromium, and a wrapper around spawned git, ollama, curl, and CLI agents; on the phone, a static manifest test over every host and fetch call site plus a proxy pass on a device. Feasible in CI for the desktop; static checks plus a manual pass for the phone. Sizes: the flag 2 to 3 days, the audit and test 3 to 4, the copy 1 to 2.

**Hide list.** Hide: Crew and its scheduler (runs even when the room is hidden); Launch (a second account); Marketplace and reviews (a grayed room invites tickets); Stack Health (an operator's view); Admin, org projects, org vault, and moderation (v2); both Currents groups, their probes, and Jev (BETA cloud calls); the Terminal room and its PTY route (an unjailed shell from the phone); the Vault room (keep project memory reachable from the project); Google Drive (OAuth plus traffic to Google); the Browser switch (gates nothing); Harbor 3B on the phone (non-commercial, and it implies the phone does the coding). Keep: Chats, Projects, Repositories, Stack, Desktop + phone, Cloud Connections (the escape hatch), Settings, Harbor Lite, voice. Keep but reword: "Sync chats across your devices" (Sidebar.tsx:291) is false, there is no chat table; the ethics screen says "checked on this device"; DeepBlue states its model's license.

**The four decisions.** License: publish the engine source so the privacy claim can be checked; which license is the CFO's call. Trial: shape is the CFO's and CMO's; on my lens, only a time trial on the entitlement row fits the privacy promise, because a first-project trial means we count projects. Founding offer: defer; technically a date on the entitlement row. Web checkout: yes for the desktop; stripe-checkout and stripe-webhook exist; the iPhone app never links to it (guideline 3.1.1).

**Definition of done.** Cannot be recorded as written, even with conditions 1 and 5: two Tailscale installs, Ollama, a 2.5 GB download, and a CPU-only coding turn do not fit in 90 unedited seconds (a 7B reads its prompt at 6.7 tokens a second on the reference box, DECISIONS.md:1324). Record the whole run unedited with a clock on screen, however long it takes, by someone other than the founder on their own hardware; then cut a clearly labelled 90-second version from it.

**One thing.** Give the phone the check and the undo, through one grant held on the machine and one daemon route, or the recording v1 depends on cannot be made.

## CMO

**Verdict.** GO WITH CONDITIONS. Narrowing the product is right, but three things must change first: the headline promise is false in code today, the definition of done cannot be recorded as written, and the price puts the promise's own "everywhere" behind the paywall.

**Conditions.**

1. Retire "no one, including us, is watching." Our own server does watch: signed-in blocks, and consent assertions too, post to our guardrail_events table, and each record carries subject, a real person's name taken from the prompt (app/src/lib/ethics.ts:122-131); those records feed an enforcement ladder that can close the account; the desktop engine calls our push-send each time a run finishes (daemon/push.ts); the catalog and update checks run without anyone tapping. Ship instead: "Your models, your keys, your computer, from your phone. We never see your code or your prompts." To make it true: hash or drop subject, keep push off until the person turns it on, make updates ask before downloading (electron/main.ts:1175 sets autoDownload = true), and make web search ask once. The sweeping line only works if the ladder stays on the device.
2. Take down the false copy in Phase 0, not Phase 2. Downloads are live under "No phone-home, ever" (viz.njk:151). Copy only, a few hours.
3. Phase 1 must make verify run on phone sessions; remote-attached skips it (loop.ts:341), so the phone never sees a green pill.
4. Keep pairing free; charge for the building, never for where you are. Chat with a paired computer is already free by an earlier ruling (DECISIONS, POST /chat), and charging before Tailscale works will earn refunds. To a stranger, "$0 local chat" reads as Ollama with a nicer window, and "$50 for pairing" reads as paying to use my own phone. Say instead: "Free: chat with your models, on your computer and your phone. Personal, $50 a year: it builds, checks, and undoes."
5. The free model in the recording must be Apache licensed, so measure qwen3:4b. On an 8 GB computer the first-run model today is the non-commercial 3B.

**Phase by phase.**

- Phase 1: the copy is part of the product. Undo: "Undo these changes", then "Undone · Redo", then "Files are back. The npm install it ran stays." The pill: "Checks pass." Every failure state gets one plain line and one button, e.g. "Your phone can't see your computer. Open Tailscale on both, same account."
- Phase 2, lines to change: oscode.js:36, setupGuides.ts:68, guidedSetup.ts:117 ("never leaves") become "stays on this device and goes only to [provider]." oscode.js:134, :243, :331; viz.njk:151, :154; privacy.njk:5; tabpages.js:54, :63 become "No analytics, no tracking. Your code and prompts never reach us. Every connection is listed in the app." tabpages.js:79, oscode.js:385, SettingsScreen.tsx:430-435: list every field sent, say a signed-in block reaches our server, cut "nothing leaves it." tabpages.js:62, oscode.js:134: "Chats, keys, and settings are encrypted." oscode.js:104: "With no signal, Harbor Lite still answers. The work waits for your computer." oscode.js:158, :171, :263: "Makes the change, runs your checks, and any task can be undone." "Harbor Light" to Harbor Lite: oscode.js:183; tabpages.js:30, :132, :139; viz.njk:68; app-review-notes.md:39. Cut the Marketplace (oscode.js:113, :264), the team tiers (:227, :278-325, :389), the team hub section (tabpages.js:156-162). Every $20 becomes $50 (oscode.js:225, :275; Paywall.tsx:38; plans.ts). ethics.njk:90 "no IP address, ever": check Supabase's request logs before it stays. app-review-notes.md:88-91: the push token is linked to the account (push-register stores user_id); also declare the email and the guardrail record; drop :93-103 with Currents.
- Channels, aimed at people who already run Ollama and Tailscale (they succeed alone): Ollama's integrations list and r/LocalLLaMA with the recording; r/selfhosted; one Show HN once the engine source is public; local-AI YouTubers given a build, not a script. No paid ads, no push to non-developers before an Apache model has a measured number.

**Hide list.** Hide: Crew and routines (never run on a real schedule); Launch (a support queue); Vault (not the v1 job); Stack Health ("saved you" is unmeasured); Terminal (a room for experts); Admin, org vault, teams (v2); Marketplace, removed rather than grayed (a grayed room teases); both Currents groups (cloud, unmeasured); Harbor unless it moves to an Apache model (license, and it blurs the phone rule); the Air program out of all copy. Keep: DeepBlue, Harbor Lite, pairing, Repositories (disk and GitHub), BYOM, Chain of Thought (off by default). Keep but reword: cloud ("on your key, asks first"); web search ("asks once, listed"); the Privacy sheet becomes "What leaves this device"; voice only after a device pass. Phone rule: anything that edits, runs, or checks happens "on your computer"; the phone asks, watches, approves, and undoes. Never "on-device coding" or "pocket coder."

**The four decisions.** License: publish the engine's source as the proof of the privacy promise, keep the app closed; say "source available", never "open source" unless OSI-approved; exact terms to the CFO and a lawyer. Trial: the first project, not a clock ("The agent is free on your first project."); a stranger may spend three days getting Ollama running. Founding offer: no free year (it teaches $0); a founding price locked while they renew; the number to the CFO. **Definition of done.** Cannot be made today: verify is skipped on phone sessions; the only measured floor model is non-commercial; an unedited 90 seconds cannot hold an install, a 1.9 GB download, a Tailscale sign-in, and a CPU model writing at 3 to 7 tokens a second. It must show, in order: a stranger, with their computer's specs on screen, doing a clean download; Tailscale as it really is; the ask typed on the phone with the teal (local) pill the whole way; a red test, then the green pill; undo with its honest sentence; "What leaves this device" and "$0 in API calls" to close. It must never show the founder's computer; a model or tailnet prepared before recording without saying so; amber anywhere; an unmarked cut; Keel or a hidden room; the words "safe", "nothing leaves", or "always on".

**One thing.** Trade "no one, including us, is watching" for "we never see your code or your prompts," make that sentence true in code, and let the app list everything else that leaves.

## CFO

**Verdict.** GO WITH CONDITIONS. A $50 product with no inference cost is a sound business; its only cost of goods is support time. Five gaps close first, or the recording sells what we may not sell.

**Conditions.**

1. Adopt the users reading of 15,000 (fact 6). Read as payers, it is $750K gross ($637K net on Apple), and at 5% conversion (assumption) it needs 300,000 users. Support (assumptions: 30 tickets per 1,000 new users in month one, 5 per 1,000 established users monthly, 10 minutes each): 15,000 users adding 1,000 a month is about 100 tickets, 17 hours a month; 300,000 users is at least 1,500 tickets, 250 hours, more than a full-time hire. Read as users, 2% to 10% conversion is 300 to 1,500 payers, $15K to $75K gross; base case 750 payers, $32K to $36K net. Fixed costs near $500 to $1,000 a year (assumption) mean profit from about 25 payers. Conversion, not reach, is the lever.
2. Record only a model we may sell (fact 5). Qwen2.5-Coder-3B is non-commercial; a $50 launch video on it tells paying customers to breach Qwen's license. Measure qwen3:4b (Apache), or record the 7B (Apache) on a 16 GB machine, or get Qwen's written permission.
3. Add phone verify to Phase 1 (fact 1). maybeVerify skips on remote-attached (loop.ts:341, profiles.ts:34), so the recording cannot happen.
4. Gate pairing as priced (fact 3). Tailscale is our costliest support path, and free users should not consume it.
5. Narrow the headline before the App Store listing (fact 2). guardrail_events sends a hash and subject to our Supabase (ethics.ts:122). A privacy label that contradicts it is an App Review and deceptive-claim exposure. Keep the ladder local, or state exactly what we record.

**Phase by phase.** Session-days, estimates. Phase 0: 2 to 2.5 plus a box run (trust with a test per vector 1.5 to 2; num_ctx 0.5). Phase 1: 5 to 8 plus a device sitting (undo 1.5 to 2; verify pill 0.5 to 1; phone verify 0.5 to 1; first run and pairing recovery 2 to 3; Apache floor 0.5; Mac signing 0.5 to 1, since unsigned builds send strangers into System Settings and our $99 program already covers signing); this phase is the margin line. Phase 2: 5.5 to 8.5 (hide flag 1 to 1.5; copy and the $50 mirror 1 to 1.5; egress audit, screen, and test 2 to 3; web checkout 0.5 to 1; trial 0.5; license 0.5 to 1). Total 12.5 to 19. Verification is the constraint: about 16 device checks are open. Not worth it for v1: team Stripe prices, a hosted license server, the Air program, the ACP listing, the sandbox, filing our own VAT.

**Hide list.** Crew and routines: hide (unverified; "why didn't it run" tickets). Launch: hide (the person's Apple account problems become our tickets). Vault: hide (two egress hosts to audit, plus sync tickets). Stack Health: hide (shows unmeasured estimates). Terminal Room: hide (an expert door and a security surface). Admin and team: hide (nothing to sell in v1; the code stays for v2). Marketplace, both Currents groups: hide (questions and cloud spend, not payers). Harbor on the phone: keep but reword (a pocket helper, never the coder, moved off the same non-commercial 3B). Default web search: keep but reword (name DuckDuckGo on "What leaves this device").

**The four decisions.**

1. License: open core. The engine under BSL 1.1: free for individuals, production use by organizations licensed by email until v2, Apache 2.0 after four years. The app stays closed. Closed protects little: the engine ships in every download, and the pay wall is honor-system against a person's own daemon; Apache gives away the paid agent. Say "source available", never "open source". The egress test, not the source, proves the app. Lawyer pass about $1,500 to $4,000 (assumption).
2. Trial: 14 days of agent and pairing, starting at the first green pill, no card. A clock that starts at install runs down while the person sets up Ollama, a 1.9 GB download, and Tailscale, and each expiry becomes a ticket. A first-project trial leaks, because a solo developer lives in one repo.
3. Founding offer: not a free year, which delays by a year the one number that matters, strangers paying. $25 for year one, then $50, refundable for 30 days, open for 60 days. On Apple a pay-up-front introductory offer; on the web a one-time Stripe coupon. At 40 founding payers (assumption) it forgoes $1,000.
4. Web checkout: yes. Apple's Small Business Program nets $42.50, handles tax and refunds, and holds to about 23,500 payers ($1M proceeds). Stripe direct nets about $47.90 (2.9% plus $0.30, plus 0.7% Billing). A merchant of record that files sales tax and VAT nets $46.50 to $47 (rates to confirm). Take the merchant of record: one person should not file EU VAT to save up to $1.40 a payer. It lets Linux and Android people pay.

**Definition of done.** $50 on both rails, gates on, and one real stranger purchase through each. The recorded model is Apache or licensed in writing and named on screen, and the stranger is on the trial, not the ungated beta. The privacy label, tagline, and "What leaves this device" match, and the egress test is green. A signed LICENSE replaces "no license granted". The first 200 strangers file fewer than 6 tickets in month one, counted in the inbox.

**One thing.** Our only cost of goods is the founder's hours, so count 15,000 as users, spend Phase 1 on the tickets nobody will need to write, and record only a model we may sell.
